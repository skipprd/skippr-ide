# Skippr IDE (VSCode Fork)

This repository builds a downloadable Skippr IDE desktop app from a VSCode fork.
It is not packaged as an external extension install flow.

## Repository Layout

- `vscode/` - upstream VSCode checkout (created by bootstrap script)
- `overlays/vscode/` - Skippr overlay files copied into the VSCode source tree
- `overlays/vscode/extensions/skippr-workbench/` - built-in Skippr module (ships in product build)
- `rust-core/` - Rust payload and domain logic used by the built-in module
- `config/product.overrides.json` - product branding overrides (`Skippr IDE` name/protocol)
- `scripts/` - bootstrap, overlay apply, build, dev, and verification scripts

## What Is Implemented

- VSCode fork bootstrap and update workflow.
- Product branding overrides for a first-party `Skippr IDE` app identity.
- Built-in Skippr workbench surface with panels:
  - Discover
  - Sync
  - Model
  - Catalog
  - Lineage
- Shared 3-pane layout across all Skippr panels.
- Rust-first payload bridge:
  - UI surface in TypeScript (required for VSCode module host)
  - Data payload generated by `rust-core` and consumed through a bridge.
- Fallback payload path if Rust runtime invocation fails.

## Prerequisites

- Node.js `22.22.1` (the scripts auto-switch with `nvm` if available)
- npm
- Rust toolchain (`cargo`)
- Git
- Build deps required by VSCode for your OS

## Bootstrap The Fork

```bash
npm install
npm run bootstrap:fork
```

This clones upstream VSCode into `vscode/` and applies Skippr overlays.

## Build A Downloadable Skippr IDE

```bash
npm run build:ide
```

This script:
- builds `rust-core`
- installs VSCode dependencies
- compiles the built-in Skippr workbench module
- compiles VSCode build outputs

## Package Artifacts By Platform And CPU

All packaging scripts emit archives to `artifacts/`.

```bash
# macOS
npm run package:darwin:x64
npm run package:darwin:arm64

# Linux
npm run package:linux:x64
npm run package:linux:arm64
npm run package:linux:armhf

# Windows
npm run package:win32:x64
npm run package:win32:arm64
```

Notes:
- Packaging scripts run `core-ci` first to generate minified build outputs required by `vscode-*-min-ci` tasks.
- Some targets require matching native runners (for example `win32:arm64`).

## Developer Mode (Hot Rebuild Loop)

```bash
npm run dev
```

This runs VSCode watch mode in the fork source tree. In another terminal:

```bash
cd vscode
./scripts/code.sh
```

For iterative development:
- keep watch running
- restart/reload the running app window as needed after UI or contribution changes
- this mode now watches only the core client + `skippr-workbench` extension for a tighter inner loop

## Re-apply Overlay After Upstream Sync

```bash
npm run apply:overlay
```

Use this after pulling or rebasing the `vscode/` checkout.

## Verification

```bash
npm run verify:fork
```

Checks:
- Rust core compiles
- overlay module exists
- overlay patch script has valid syntax

## GitHub Actions

Workflow: `.github/workflows/skippr_ide_build_release.yml`

- `verify` job validates bootstrap + rust/tooling.
- `package` job runs a platform/arch matrix and uploads artifacts.
- `release` job publishes tag builds (`v*`) to GitHub Releases.

Matrix includes all requested platform/arch targets; entries without reliable hosted runners are declared but disabled by default in workflow matrix (`enabled: false`).
